# lecture-analysis

> **강의 녹취를 넣으면, 근거가 인용된 분석 리포트가 나옵니다 — 점수 없이, 오디오는 로컬에서.**

클로바노트 녹취(txt)와 강의 녹음을 폴더째 건네면, 말속도·침묵·헤징 같은 **측정 지표**와 잘된 것/아쉬운 것·다음 액션 후보를 **모든 항목에 인용 근거를 달아** 리포트로 발행합니다. Claude Code 스킬(대화)로도, 터미널에서 `analyze.sh` 직접 실행으로도 동일하게 동작합니다 — 스킬은 편의 레이어일 뿐 로직을 갖지 않습니다.

## 무엇이 나오나요?

1회 분석이 끝나면 세션 폴더의 `outputs/`에 파일 두 개가 생깁니다.

| 파일 | 용도 |
|---|---|
| **`{강의명}_분석리포트_{날짜}.html`** ★ | **공유용 최종본.** 브라우저로 열면 요약 카드 + 차트 6종 + 접이식 원자료 부록. 외부 CDN 참조가 없어 보안망에서도 열리고, 브라우저 인쇄만으로 PDF가 됩니다. 제3자에게 주는 파일은 이것 하나입니다 |
| **`{강의명}_분석데이터_{날짜}.md`** | **데이터 레이어.** 모든 수치·인용의 원본 — 검색·diff·후속 파이프라인용이며, 다음 액션 확정(체크박스) 기록의 원본입니다 |

두 파일 모두 같은 **3층 구조**입니다:

```
A층  한눈 요약(1화면)   목표 점검 · 지표 한 줄 + 직전 대비 · 하이라이트 · 다음 액션 후보 · 측정 신뢰도
B층  상세              전달 지표 · 정밀 음성 지표 · 질문/참여 · 시간 배분 · 트러블 타임라인 · 액션 체크박스
C층  부록              인용 증거 전문(B층 앵커의 목적지) · 측정 정의 · 실행 메타
```

**점수·등급·좋음/나쁨 판정은 어느 층에도 없습니다.** ▲▼→는 방향 표시일 뿐이고, 모든 관찰은 C층의 인용 전문으로 내려가 확인할 수 있습니다. 근거가 없는 항목은 개수를 맞추기 위해 남기지 않고 폐기합니다(폐기 수는 C2에 집계). 지표 정의의 SSOT는 `references/metrics.md`입니다.

## 빠른 시작

### 1. 플러그인 설치

```
/plugin marketplace add Joseph-Cha/lecture-analysis
/plugin install lecture-analysis@joseph-cha-plugins
```

설치 후 Claude Code를 재시작하세요(플러그인은 시작 시 로드됩니다).

### 2. 데이터 폴더 준비

한 회차 분량의 녹취록 txt와 녹음 파일을 **폴더 하나에** 모읍니다(하위 폴더는 보지 않습니다). 원본은 이동·복사되지 않고 경로로만 참조됩니다.

### 3. 대화로 시작

```
이 폴더 강의 분석해 줘: ~/강의/3회차
```

강의명·강의 날짜·교시 매핑(오디오↔txt)·실명 마스킹 목록(`mask_names` — **[데이터는 어디로 가나요?](#데이터는-어디로-가나요)를 꼭 읽으세요**)을 Claude가 차례로 확인한 뒤 파이프라인을 실행하고, 끝나면 실행 위치의 `LECTURE_ANALYSIS/` 세션 폴더에서 리포트를 안내합니다. 녹음 전사가 필요하면 전사 환경 설치(`setup.sh`, 약 1.1GB)도 대화에서 안내합니다. 오디오가 있으면 교시당 수 분~수십 분 걸립니다 — 완료된 스테이지는 재실행 시 SKIP되므로 중단·재개는 무해합니다.

### 터미널에서 직접 쓰기 (선택)

스킬은 편의 레이어일 뿐이라 저장소를 클론해 직접 돌려도 동일합니다:

```bash
git clone https://github.com/Joseph-Cha/lecture-analysis.git
cd lecture-analysis/skills/lecture-analysis
bash setup.sh                                      # (선택) 전사 환경 — ffmpeg는 별도(brew install ffmpeg)
bash analyze.sh init <데이터 폴더> --name "3회차_판다스"
bash analyze.sh run LECTURE_ANALYSIS/<세션 폴더>/manifest.toml
```

`init`이 만든 manifest에서 실행 전 **세 가지를 확인**합니다:

- `date` — init은 오늘 날짜로 채웁니다. **실제 강의일로 고치세요**(산출물 파일명에 들어갑니다).
- 교시 매핑(오디오↔txt) — 어긋나면 말속도·침묵이 통째로 엉뚱한 교시의 값이 됩니다.
- `mask_names` — 녹취에 등장하는 실명 목록(기본값은 빈 목록).

## 왜 lecture-analysis인가?

- **점수가 아니라 관찰** — "83점"이 아니라 "헤징 212문장, 시간당 34.5회"를 줍니다. 등급·총평·감정 해석은 설계상 존재하지 않습니다(수강생 평가 사용 금지).
- **모든 주장에 인용 근거** — 잘된 것/아쉬운 것 각 항목이 C층의 발화 인용 전문으로 앵커됩니다. 근거가 검증되지 않은 항목은 발행 전에 폐기됩니다.
- **오디오는 기기 밖으로 나가지 않습니다** — 전사(whisper)는 완전 로컬. 외부로 나가는 것은 마스킹을 거친 텍스트뿐이며, 그마저 실행 전 확인 게이트가 있습니다.
- **결정론 + 멱등** — 수치 지표는 LLM 없이 계산되어 재실행해도 같은 값이고(같은 입력·같은 모델 기준), 파이프라인은 완료 지점부터 이어 돕니다.
- **공유는 파일 하나** — html 한 파일에 차트까지 인라인되어 있고, 발행 직전 내부 링크 무결성과 로컬 경로 비노출을 자동 검증합니다.

## 동작 방식

```
데이터 폴더 (한 회차: 녹취록 txt + 녹음 파일)
    │
    ▼  analyze.sh init
manifest.toml — 입력 계약                ★ 사람이 확인: 강의 날짜 · 교시 매핑 · mask_names
    │
    ▼  analyze.sh run
s10  전사        오디오 → 텍스트 세그먼트 (whisper, 완전 로컬 — .venv 없으면 건너뜀)
s20  파싱        녹취록 txt 파싱 · 강사 식별(점유율 60% 게이트) · 실명 마스킹
s30  의미 관찰   LLM: 사과·자문자답·트러블 추출 + 강사 라벨 교차 확인
s40  구조 관찰   LLM: 질문·uptake·타임라인·계획 대비 커버리지
s50  지표 계산   말속도·침묵·헤징·필러 등 결정론 수치 (LLM 없음)
s60  목표 점검   직전 회차 액션 달성 판정 (직전 데이터 없으면 '첫 분석')
s65  리뷰        잘된 것/아쉬운 것/다음 액션 후보 — 근거 없는 항목은 폐기
s70  데이터 발행  분석데이터 md (3층 리포트 원본)
s80  리포트 발행  분석리포트 html + 세션 README — 발행 전 링크·경로 노출 검증
    │
    ▼
LECTURE_ANALYSIS/{강의명}_{일시}/outputs/   ← 최종 산출물
```

실패하면 그 스테이지에서 멈추고 원인별 종료 코드를 내보냅니다 — [문제가 생기면](#문제가-생기면-종료-코드).

## 커맨드

아래 명령은 모두 스킬 폴더(`skills/lecture-analysis/`) 기준입니다.

| 커맨드 | 하는 일 |
|---|---|
| `bash analyze.sh init <데이터 폴더> [--name <강의명>]` | 세션 폴더 + manifest.toml 뼈대 생성(파일 자동 나열). `--name` 생략 시 데이터 폴더명이 강의명 |
| `bash analyze.sh run <manifest.toml>` | 전체 실행 — 완료 스테이지는 SKIP, 실패 교시는 재실행 시 자동 재시도 |
| `bash analyze.sh run <manifest.toml> --force s30` | s30부터 강제 재생성 — 정의·프롬프트를 바꿔 재발행할 때만(실패 재시도에는 불필요) |
| `bash analyze.sh status <manifest.toml>` | 산출물별 진행 상태(실패 마커 포함) |
| `bash setup.sh` | (선택) 전사용 `.venv` + mlx-whisper 설치 |

- `init`은 **실행한 자리**에 `LECTURE_ANALYSIS/`를 만듭니다 — 작업 폴더에서 실행하세요.
- 강의명 슬러그 규칙: 한글 음절·영숫자·`-`·`_`는 유지, 공백은 `_`, 나머지는 `-`로 치환. 쓸 글자가 하나도 남지 않으면 exit 2로 이름을 다시 요구합니다.
- 폴더에 txt·오디오가 하나도 없으면 경고를 찍되 뼈대는 만듭니다 — 폴더가 맞는지 먼저 확인하세요.

## 산출물 구조

1회 분석 = 세션 폴더 하나. 입력 데이터 폴더는 읽기만 하고, 산출물은 전부 실행 위치의 `LECTURE_ANALYSIS/` 아래에 쌓입니다.

```
<실행 위치>/LECTURE_ANALYSIS/
└── {강의명}_{YYYYMMDD-HHMM}/                  # 세션 폴더 — 1회 분석 = 1폴더
    ├── README.md                              # 내비게이션 가이드
    ├── manifest.toml                          # 입력 계약(교시·마스킹·측정 구간) = 재실행 진입점
    ├── outputs/                               # ── 최종 산출물 ──
    │   ├── {강의명}_분석리포트_{YYYYMMDD}.html   # ★ 공유용(제3자에게 주는 유일한 파일)
    │   └── {강의명}_분석데이터_{YYYYMMDD}.md     # 데이터 레이어(검색·diff·액션 확정 기록)
    └── artifacts/                             # ── 중간 산출물(스테이지 계약물) ──
        ├── whisper/pNN.json                   # s10 전사 세그먼트
        ├── parsed/pNN.json                    # s20 파싱 + 강사 식별 + 마스킹본
        ├── llm/pNN_semantic.json              # s30 사과·자문자답·트러블
        ├── llm/pNN_structure.json             # s40 질문·타임라인·커버리지
        ├── llm/goal_check.json                # s60 직전 액션 판정
        ├── llm/review.json                    # s65 잘된 것/아쉬운 것/액션 후보
        ├── metrics.json                       # s50 결정론 지표
        └── report_data.json                   # s80 차트 원천 수치(SSOT 검증용)
```

**파일명 규칙** — `{강의명}`은 manifest `[session] name`, `{YYYYMMDD}`는 `[session] date`(강의 날짜, 실행 시각이 아님)에서 파생됩니다. 날짜·이름을 고치고 재발행하면 파일명도 따라 바뀌며 옛 이름의 파일은 남습니다 — 새 리포트 확인 후 지우면 됩니다. B7 액션 확정(`- [x]`)은 s70이 옛 이름 파일에서 **자동 이관**하고 몇 건을 옮겼는지 알려 줍니다.

**html / md 역할 분담**

- **분석리포트 html**: 로컬 절대 경로·실행 메타를 싣지 않는 공유용. 차트의 모든 수치는 md 표·`metrics.json`·`report_data.json`에 동일하게 존재합니다.
- **분석데이터 md**: 실행 메타(모델·스테이지 상태)는 이쪽 C3에만 있습니다.
- s80은 발행 직전 **내부 링크 무결성**(깨진 앵커 0건)과 **경로 비노출**(세션·입력·계획 폴더·`$HOME`이 html 본문에 없을 것)을 검증하고, 실패하면 exit 2로 발행을 멈춥니다.
- 세션 `README.md`도 s80이 씁니다 — html이 이미 있어 s80이 SKIP된 세션에는 없을 수 있고, `python3 scripts/s80_html.py <manifest> --force`로 재발행하면 생깁니다.

**다음 액션 확정은 사람이 합니다** — 분석데이터 md의 B7 체크박스를 `- [x]`로 바꾸고 `python3 scripts/s80_html.py <manifest> --force`를 돌리면 html의 상태 라벨이 추천 → 강사 확정으로 바뀝니다. 세션 폴더는 서로 독립이라 s60의 직전 액션 판정은 배포판 기본으로 항상 '첫 분석'입니다 — 확정 목록은 다음 강의를 준비할 때 사람이 읽는 기록입니다.

## 데이터는 어디로 가나요?

수강생·강사의 발화가 담긴 데이터를 다루므로, 실행 전에 이 표를 꼭 확인하세요.

| 데이터 | 어디까지 가나 |
|---|---|
| 녹음 파일(오디오) | **기기 밖으로 나가지 않습니다** — 전사(s10)는 완전 로컬 |
| 전사 텍스트(녹취 본문) | s30·s40·s60이 `claude -p`로 **Anthropic(국외)에 전송** — `mask_names`의 실명을 `[이름N]`으로 치환한 뒤 |
| 계획 문서(`[session] plan`) | s40이 커버리지 판정용으로 **전송** — 같은 `mask_names` 규칙으로 마스킹. 계획 문서에는 담당자·수강생 실명이 전사보다 자주 적혀 있으니 그 실명도 목록에 넣으세요 |
| s65(리뷰) 입력 | 원문 재전송 없음 — 검증을 통과한 상류 산출물만 싣습니다(근거 없는 인용을 새로 만들 여지를 없애는 설계) |
| 산출물 | 전부 로컬 `LECTURE_ANALYSIS/` — 공유는 html 한 파일만 |

**`mask_names`의 기본값은 빈 목록입니다.** 비워 두면 녹취 본문이 원문 그대로 전송됩니다 — s20이 경고를 찍지만 차단하지는 않습니다(실명이 없는 녹취도 있어 판단은 사람이 합니다). 발화에 실명·소속·연락처가 섞여 있으면 반드시 채우세요(화자 라벨은 원래 `참석자 N` 익명입니다).

**운영 규칙**

- 수강생 음성 포함 시 **사전 고지·동의**(B2B는 계약 조항, 공개강의는 모집 페이지 고지).
- 녹음 파일 **외부 공유·해외 SaaS 업로드 금지**(음성권·국외이전).
- 녹취록 내보내기 전 강의 전후 잡담(정산 논의 등) **트리밍**(측정 구간 `bounds`가 2차 방어선).
- 분석 결과를 **수강생 평가·수료 판정에 사용 금지**(AI기본법 고영향 재검토 트리거).

## 문제가 생기면 (종료 코드)

`run`은 실패한 스테이지에서 멈추고 `중단: sNN (exit N)`으로 위치를 알려 줍니다.

| 코드 | 뜻 | 대응 |
|---|---|---|
| 0 | 정상 | `outputs/`에 분석리포트 html · 분석데이터 md + 세션 `README.md` 발행 완료 |
| 2 | 입력 오류(s80의 링크·경로 검증 실패 포함) | 메시지가 가리키는 파일·필드를 고치고 다시 `run`. s80 검증 실패는 `--force s70`으로 상류 재생성 후 재실행 |
| 3 | 강사 식별 실패 — (a) 점유율 60% 미만 (b) LLM 교차 확인 불일치 | (a) 함께 출력되는 화자 샘플을 보고 manifest `[speakers] instructor_label`을 수동 지정 — 그 라벨이 해당 교시에 실제로 있어야 진행됩니다(있으면 저점유율이어도 경고 후 진행). (b) LLM이 준 사유를 읽고 지정한 라벨을 재검토 |
| 4 | LLM 실패(재시도 후) | **`--force` 없이 그냥 다시 `run`** — 실패 교시만 재시도됩니다. 실패가 계속되면 리포트가 나오지 않습니다(건너뛰기 플래그 없음) — 포기하려면 그 교시를 manifest에서 빼세요(A5·C2에 제외 흔적이 남습니다) |

`ffmpeg` 관련: `.venv`가 없으면 s10을 건너뛰고 정밀 음성 지표 없이 계속 진행하지만, **`.venv`는 있는데 ffmpeg가 없으면 s10이 exit 2로 멈춥니다** — `brew install ffmpeg` 후 다시 `run` 하세요(setup.sh는 ffmpeg를 설치하지 않습니다).

## 값을 읽기 전에 (한계)

- **필러는 하한** — 단독 토큰 `어`·`음`만 세고, ASR가 이미 지운 것은 못 잡습니다. 절대값 비교 금지.
- **자문자답은 상한(`≤N`)** — 단일 레코더가 오프마이크 응답을 놓쳐 "응답 없음"으로 보일 수 있습니다. 녹음 환경이 같으면 추세 비교는 유효합니다.
- **대기 시간은 구두점 근사** — whisper가 물음표를 찍어 준 세그먼트만 질문으로 봅니다.
- **오디오만 있는 교시는 화자 미분리** — 강사 한정 지표가 "혼합 상한"이 되고, 헤징 시간당 분모에서 제외됩니다(누락 표기됨).
- **잘된 것/아쉬운 것이 3개 미만일 수 있습니다** — evidence가 비었거나 실재하지 않는 참조를 든 항목은 폐기하고, 남은 것만 발행합니다. 개수를 맞추려 근거 없는 항목을 남기지 않는 정직 우선 설계입니다(폐기 수는 C2에 집계).
- **전달 지표는 학습 성과 지표가 아닙니다**(문헌 충돌). 개인별 판단·평가 금지.

## 요구사항

- **macOS + Apple Silicon** — 전사(s10)가 `mlx-whisper`를 씁니다. 전사를 안 쓰면 이 제약도 없습니다.
- **python3** — 전사를 제외한 모든 스테이지는 시스템 python3 표준 라이브러리만 씁니다.
- **[Claude Code](https://docs.anthropic.com/claude-code) CLI** — LLM 스테이지(s30·s40·s60·s65)가 `claude -p`로 호출합니다(로그인 필요).
- **ffmpeg** (`brew install ffmpeg`) — 오디오 디코딩용. 전사를 쓸 때만 필요합니다.
- **화자 분리 녹취록(txt)** — 화자 라벨(`참석자 N`)과 타임스탬프가 블록 단위로 반복되는 녹취록 내보내기 형식을 읽습니다. 녹취록 없이 녹음 파일만 있는 교시는 화자 미분리 모드로 떨어집니다.

whisper 모델(`large-v3-turbo`, 약 1.5~1.6GB)은 첫 전사 때 `~/.cache/huggingface`로 자동 다운로드됩니다(저장소 밖). setup.sh 실측: 최초 39초 / 재실행 1.5초(멱등) / `.venv` 1.1GB.

## 고급 설정

### 환경변수

| 변수 | 기본값 | 용도 |
|---|---|---|
| `LA_MODEL` | (로그인 플랜 기본 모델) | LLM 스테이지 모델 교체 — 바꾸면 회차 간 비교 조건이 달라집니다. C3에 남는 값은 s70 실행 시점의 환경변수이지 산출물을 만든 모델이 아닙니다(중간에 바꿔 이어 실행하면 어긋남). `whisper=`는 s10 산출물에서 되읽으므로 항상 정확합니다 |
| `LA_WHISPER_MODEL` | `mlx-community/whisper-large-v3-turbo` | 전사 모델 교체(`…/whisper-tiny` 등 — 빠르지만 오인식 증가). 리포트 C3에 기록 |
| `LA_CLAUDE_BIN` | `claude` | `claude` CLI 경로. 테스트 스텁 주입 seam |
| `LA_VENV_PY` | `<스킬>/.venv/bin/python` | s10이 쓰는 파이썬. 테스트 seam |
| `LA_GROWTH_DIR` | (미지정) | 추세 CSV 폴더 — 아래 참고 |

**설정 방법** — 변수 성격에 따라 알맞은 방법이 다릅니다:

```bash
# ① 일회성: 명령 앞에 붙이면 그 실행에만 적용 — 측정 조건을 바꾸는 변수(LA_MODEL 등)에 권장
LA_MODEL=claude-sonnet-5 bash analyze.sh run <manifest.toml>

# ② 터미널 세션 동안 유지 — 창을 닫으면 사라짐
export LA_GROWTH_DIR=~/lecture-growth

# ③ 영구: 새 터미널부터 자동 적용 — 한 위치로 고정해야 하는 LA_GROWTH_DIR에 권장
echo 'export LA_GROWTH_DIR="$HOME/lecture-growth"' >> ~/.zshrc
```

스킬(대화)로 쓸 때는 "추세 기록도 켜서 돌려줘(폴더는 ~/lecture-growth)"처럼 말하면 ① 방식으로 실행되고, `~/.claude/settings.json`의 `env` 항목에 넣으면 Claude가 실행하는 모든 명령에 자동 적용됩니다:

```json
{ "env": { "LA_GROWTH_DIR": "/Users/<사용자>/lecture-growth" } }
```

단, 측정 조건을 바꾸는 변수(`LA_MODEL`·`LA_WHISPER_MODEL`)는 영구 설정에 넣지 않는 편이 좋습니다 — 설정해 둔 사실을 잊으면 회차 간 비교 조건이 바뀐 줄 모르고 지표를 읽게 됩니다(설정 여부는 리포트 C3에서 확인).

### 회차 추세 CSV — 개인용 opt-in (`LA_GROWTH_DIR`)

회차 간 추세는 **배포판 기본 기능이 아닙니다.** `LA_GROWTH_DIR`을 지정한 실행에서만 s70이 `<LA_GROWTH_DIR>/trend_metrics.csv`에 세션 1행을 upsert하고 s80이 추세 차트를 그립니다. 미지정이면 기록도 비교도 하지 않습니다(리포트 C3에 `추세 CSV: 미기록`으로 남음).

```bash
LA_GROWTH_DIR=~/lecture-growth bash analyze.sh run <manifest.toml>
```

<details>
<summary><b>추세 CSV 상세 — 열 정의와 빈 칸 규칙</b></summary>

**회차 키는 손으로 채워야 합니다.** upsert·비교의 그룹 키는 `(project, session)`인데 `init` 뼈대에는 두 값이 없습니다 — manifest `[session]`에 `project = "…"`·`id = "sNN"`을 직접 적지 않으면 모든 회차가 같은 한 행을 덮어쓰고 직전 대비 비교가 서지 않습니다. 폴더 위치도 한 곳으로 고정하세요(갈라지면 비교가 조용히 리셋됩니다).

| 열 | 뜻 |
|---|---|
| `date` | 세션 날짜(manifest `[session] date`) |
| `project` / `session` | 추세 그룹 키 / 회차 키 — **비면 회차 구분이 없어집니다** |
| `bounds_h` | 측정 구간 합계(시간) |
| `apology_n` | 협의 사과 건수(습관성·사전 양해 제외) |
| `selfqa_max` | 자문자답 상한(≤) |
| `hedging_n` / `hedging_per_h` | 헤징 문장 수 / 시간당 — 분모는 `text_hours`(전사 있는 구간)라 `bounds_h`와 다를 수 있음 |
| `trouble_n` / `trouble_min` | 진행이 실제 정지한 장애 건수 / 총 분 |
| `speech_rate_spm` | 말속도(분당 한글 음절) — 오디오 없으면 빈칸 |
| `silence_min` | 3초 이상 무발화 총 분 — 오디오 없으면 빈칸 |
| `filler_min_n` | 필러 하한 |
| `notes` | 비고. **s70이 항상 빈 값으로 덮어씁니다** — 손 메모는 재발행 시 사라지니 오래 남길 비고는 리포트 본문에 |

**빈 칸 = 미측정**입니다. 직전 대비 표시(▲▼→)는 빈 칸을 만나면 아무 표시도 붙이지 않습니다 — 없는 비교를 `→`로 그리면 "변화 없음"이라는 가짜 정보가 되기 때문입니다. 오디오가 없으면 음성 파생 열이, 전사가 한 교시도 없으면 텍스트 파생 열 전부가 빕니다. 미측정을 `0`으로 적으면 다음 회차가 그것을 기준선으로 읽어 거짓 개선이 굳습니다.

**부분 결손은 값으로 기록됩니다.** 6교시 중 2교시만 전사가 있으면 `hedging_n`은 그 2교시 합계 — 0이 아니라 **하한**이고, 열만 봐서는 전 교시 측정과 구분되지 않습니다(`text_hours < bounds_h`가 유일한 힌트). 회차 간 절대값을 인용하기 전에 리포트 A5·C2의 미가용 목록에서 그 세션의 전사 커버리지를 먼저 확인하세요.

</details>
